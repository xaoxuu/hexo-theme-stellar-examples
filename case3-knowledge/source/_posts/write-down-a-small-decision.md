知识库需要不断作选择：两份相近的资料要不要合并，旧标签是否保留，某个页面应该放在博客还是文档里。结论写在配置里，理由却常常只存在当时的记忆中。

<!-- more -->

## 从一个具体分歧开始

假设知识库里同时有“写作方法”和“写作工具”两个目录，有些文章在两边重复出现。眼前的问题不是寻找一套永远正确的分类，而是减少重复维护，同时保留容易找到文章的入口。

先把候选做法并排写下来，才能看见它们分别解决了什么，又带来了什么。

{% grid bg:box w:220px gap:16px %}
<!-- cell -->
**保留两个目录**

入口明确，读者可以直接按目的浏览。需要为交叉文章指定唯一正文，再从另一处建立链接，避免两份内容更新不同步。
<!-- cell -->
**合并为一个目录**

维护位置减少，但浏览时需要再借助标签区分方法与工具。原来的页面地址和已有链接也需要逐一检查。
{% endgrid %}

## 记录当前选择的条件

如果重复文章只有几篇，暂时保留目录、改用链接就可能足够。这个选择依赖“内容规模较小”和“旧入口仍有人使用”两个条件。把条件写出来，比单独写一句“决定不合并”更有价值。

{% note color:yellow 事实与假设分开 文章数量可以直接核对；读者偏好如果没有观察依据，就标成待验证的假设。 %}

## 为将来的重新讨论留门

{% folding color:cyan 一页决策记录可以包含什么 %}
- **背景：** 两个目录出现重复正文，修改一处后容易忘记另一处。
- **选择：** 保留目录，每篇文章只维护一份正文。
- **理由：** 当前重复范围小，先解决同步问题，不扩大路由调整。
- **代价：** 需要为交叉内容补充清晰的链接说明。
- **回访条件：** 如果新文章持续无法确定归属，再讨论目录边界。
{% endfolding %}

回访条件不是给决定设置一个自动失效日期。它只是提醒未来的自己：当初的结论是为了回答特定问题，条件变化以后，可以重新讨论，而不必猜测过去为什么坚持这样做。
