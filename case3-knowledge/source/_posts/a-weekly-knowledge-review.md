一周里保存下来的材料可能散落在浏览器、手机和聊天记录中。到了整理时间，如果同时打开所有入口，往往还没开始判断内容，就先被数量压住了。

<!-- more -->

## 只选择一个收集箱

我的起点是本周临时记事页。先把每条材料放回当时的问题里：为什么保存它？这周还需要它吗？如果已经想不起用途，就先放到待确认区，不为了“收集过”而强行写成永久笔记。

下面是一轮短回访的顺序。它不是必须严格计时的流程，哪一步发现了值得展开的问题，就在那里停下来。

{% timeline %}
<!-- node 浏览：恢复上下文 -->
逐条查看标题和备注。为缺少说明的链接补一句保存原因，确认哪些材料属于同一个问题。
<!-- node 整理：保留一个可用结果 -->
选择最有用的一组材料，写成一条能独立理解的笔记。重复内容合并引用，尚未验证的部分明确留白。
<!-- node 连接：回到现有结构 -->
寻找一条已经存在的相关笔记，说明两者关系。可能是补充例子，也可能是修正了先前的结论。
<!-- node 结束：写下下一步 -->
只留一个能够继续的动作，例如“用本周的项目记录试一次新提纲”，而不是笼统地要求继续完善知识库。
{% endtimeline %}

## 给空白笔记一个起笔句

有时材料已经选好，还是不知道从哪写起。我会先复制下面这一行，把后半句接完，再逐步补充背景和例子。

{% copy 我保存这条材料，是因为它能帮助我回答： %}

这句话写不下去，也是一种信息：材料可能暂时没有用途，或者问题还需要再缩小。先放下它，不必用更多标签掩盖不确定。

## 结束时检查能否继续使用

回顾结束后，我会重新打开刚整理的笔记，看它是否有明确标题、必要上下文和一个相关入口。能被下一次工作用上，比收集箱数字变成零更重要。

经过几轮这样的整理，知识库的变化未必很显眼，却会逐渐少一些孤立材料，多一些解释得清楚的关系。每周只清理一个入口，也能让这个过程持续下去。
