普通段落、标题和列表已经能完成大部分说明。只有当读者需要额外的提醒、比较或可选细节时，再加入标签组件。每一种组件都应该有清楚的内容用途。

## 提醒与补充使用不同结构

{% note color:cyan 必须读到的信息 把影响下一步操作的条件放在正文或提示块中，让读者经过这里时就能看到。 %}

`note` 适合一段短提醒。如果内容包含多个段落或列表，使用 `box` 更容易保持结构：

{% box color:green 一个完整示例应包含 %}
- 文件应该放在哪里。
- 可以直接对照的字段与正文。
- 操作完成后应该出现的页面或状态。

不要只给一个孤立片段，让读者猜测它属于哪个文件。
{% endbox %}

{% raw %}
```liquid
{% note color:cyan 提醒标题 这里填写一段短说明。 %}

{% box color:green 示例内容 %}
这里可以放多段 Markdown，也可以加入列表。
{% endbox %}
```
{% endraw %}

## 折叠容纳可选的解释

{% folding color:yellow 为什么不把关键步骤放进折叠？ %}
折叠后的内容默认不展开。把完成任务必需的命令藏在这里，读者可能直接跳过，从而无法继续。它更适合补充原理、展示完整日志，或回答一个并非所有人都会遇到的问题。
{% endfolding %}

行内强调可以使用 {% mark mark color:yellow tip:只突出这一小段，不替代完整的解释。 %}。提示文字用于补充，正文仍然需要在没有悬停操作时读得通。

## 比较时选择合适的容器

{% grid bg:box w:220px gap:16px %}
<!-- cell -->
**选项卡 tabs**

同一个任务有多种操作方式，读者通常只需要其中一种。例如独立站点与示例仓库使用不同的构建命令。
<!-- cell -->
**网格 grid**

几个对象需要同时比较，每个对象又包含一小段说明。屏幕空间不足时，应当让卡片自然换行。
{% endgrid %}

选项卡中的每一组使用 `<!-- tab 标题 -->` 分隔。下面是可复制的写法；实际显示效果可以在[写作指南](../authoring-guide/)中查看。

{% raw %}
```liquid
{% tabs %}
<!-- tab 第一种方式 -->
这里填写第一种方式的步骤。
<!-- tab 第二种方式 -->
这里填写第二种方式的步骤。
{% endtabs %}
```
{% endraw %}

## 写完以后读一遍普通正文

暂时忽略颜色与边框，检查段落是否仍然说明了对象、原因和操作。如果只能靠组件标题才能猜出上下文，先补齐文字，再调整展示方式。组件负责组织内容，准确的说明仍然来自正文。
