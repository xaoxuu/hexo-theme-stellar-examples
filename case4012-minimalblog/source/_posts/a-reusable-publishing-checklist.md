每次发布前都临时想一遍“还要检查什么”，很消耗注意力。清单写下来以后，写作时专心写字，发布时照着走一遍就好。

<!-- more -->

## 清单按读者的路径排列

我按读者的顺序整理这份清单：从首页进入文章，再从文章回到列表。

{% timeline %}
<!-- node 首页 -->
标题与摘要能否让读者判断这篇是否相关？列表里的日期和分类是否正确？
<!-- node 正文 -->
标题层级是否连续，代码能否复制，图片是否有说明，链接是否指向正确页面。
<!-- node 返回 -->
文末的上一篇、下一篇和相关入口是否仍能到达目标页面。
{% endtimeline %}

## 用可以观察的结果收尾

“检查完毕”说明不了任何事。把每条写成能看到的结果，比如“侧栏出现新标题，点击后进入文章”。漏掉一步时，自己立刻就能发现。

{% checkbox checked:true color:green 首页能看到更新后的标题与摘要。 %}
{% checkbox checked:false color:cyan 文末的相邻文章入口都能打开。 %}
{% checkbox checked:false color:cyan 窄窗口下正文与代码块都能正常阅读。 %}

## 清单也需要维护

添加新的组件或调整栏目结构以后，把新增的检查补进清单。清单会随着站点一起变化，每次都从同一份开始。

{% note color:yellow 一处维护 清单只保留一份，放在自己随时能打开的地方，例如草稿目录里的一个 Markdown 文件。 %}
